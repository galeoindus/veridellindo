# Source review and maintenance report — 27 November 2026

## Scope reviewed

This review was performed against the supplied `veridellindo-main.zip`, not a
live deployment. The extracted source contains 251 files, including the main
single-page app, 22 HTML entry points, 13 published article pages, Amigo chat,
Cloudflare Pages Functions, an optional standalone Worker, release/audit
scripts, and the existing Node test suite.

The existing page structure, routes, article content, public API paths, and
main feature connections were retained. Changes below are deliberately
incremental rather than a replacement of the site architecture.

## High-priority defect fixed: retired Workers AI model

The same retired model ID, `@cf/meta/llama-3.2-3b-instruct`, was active in the
Amigo selector and the model allowlists used by the Pages Function and the
optional standalone Worker. Cloudflare's 5 November 2026 notice states that
this model stops returning responses from 20 November 2026 and returns HTTP
`410 Gone` / error `5028`. The notice recommends
`@cf/google/gemma-4-26b-a4b-it` for smaller-model workloads:

- https://developers.cloudflare.com/changelog/post/2026-11-05-planned-model-deprecations/
- https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/

Implemented:

1. Switched the Pages Function allowlist to Gemma 4.
2. Added Gemma 4 to the optional standalone Worker allowlist.
3. Replaced the retired entry in Amigo's model selector.
4. Added safe migration for existing `amigo2_settings` records. A saved
   selection of the retired ID is changed to Gemma 4 before settings are saved.
5. Corrected the Amigo engine/status label to display “Gemma 4”.
6. Added API regression coverage for model advertisement and explicit routing,
   plus a cross-surface model-catalog test.

The retired identifier remains only in the compatibility migration and tests;
it is not advertised or sent to the Workers AI endpoint as an active option.

## Security and response handling

Cloudflare documents that Pages `_headers` rules are applied to static asset
responses, not to responses generated by Pages Functions. The project already
had `_headers`, but that alone did not secure `/api/*` Function responses.
Reference: https://developers.cloudflare.com/pages/configuration/headers/

Implemented in `functions/_middleware.js`:

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Frame-Options: DENY`
- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Resource-Policy: same-origin`
- HTTPS-only HSTS
- API no-store/CDN no-store, `X-Robots-Tag: noindex`, and a restrictive
  fallback Content Security Policy when one is not already present
- HTML no-store headers and the existing page marker

Static assets are left to the existing `_headers` policy, and streaming response
bodies are preserved. Tests cover API JSON, HTML, untouched static assets, and
SSE streams.

The existing chat/image request guards and input validation were retained.
The code's in-memory rate counters are per isolate and therefore best-effort,
not a global account-wide quota. For production abuse controls, configure
Cloudflare WAF rate-limiting rules for the API paths in the Cloudflare dashboard:
https://developers.cloudflare.com/waf/rate-limiting-rules/

## Interface improvements

- Main search composer: more rounded card shape, layered translucent surface,
  clearer focus state, matching gradient send action, and a floating suggestion
  panel with matching borders/shadow.
- Theme behavior: light and dark theme surfaces have explicit treatments so the
  search card does not become low-contrast when the theme changes.
- Accessibility preferences: blur is removed when reduced transparency is
  requested; nonessential motion is reduced when reduced motion is requested.
- Amigo: the chat composer now uses the same glass-like visual language with
  distinct light/dark treatments and visible keyboard-focus outlines.
- Existing markup and composer behavior were kept; this is a stylesheet-level
  improvement rather than a rewrite of keyboard handling or search submission.

## Build and release reliability

A downloaded ZIP does not contain `.git`. Previously, build stamping could fail
when asked for a commit SHA from such an archive. `scripts/stamp-build.mjs` now
uses a deterministic seven-character source-snapshot fingerprint when Git
metadata is unavailable, while keeping real Git SHAs for normal checkouts and
CI-provided `BUILD_COMMIT` values. `assets/version.json` records
`revisionType: "snapshot"` or `"git"` so the identifier is not misrepresented.

The release version for this update is `6.10.67`.

## Usage and billing wording corrected

Workers AI requires no provider API key when the Cloudflare `AI` binding is
configured, but this does not mean unlimited free inference. The comments in
the chat, image and Wrangler configuration now describe the included daily
allocation and plan-dependent usage rather than implying unlimited free use.

Before deployment, confirm the `AI` binding exists for both Production and
Preview in Cloudflare Pages settings. The relevant binding name is `AI`, as in
`wrangler.toml`.

## Test and audit results

The final verification section in the delivery message lists the exact command
results. The suite is not considered fully green when a required dependency
cannot load: any tests blocked by the unavailable `jsdom` install are reported
as environment-blocked rather than counted as passing assertions.

Final results in this environment (Node 22.16.0):

- `npm run doctor`: **6/6 checks passed** (modules, pages, deep audit, scan,
  health and drift).
- `npm test`: **210 passed; 6 blocked at module load**. The six affected test
  files could not import `jsdom` because the attempted `npm ci` did not complete
  and `node_modules/jsdom/index.js` is absent. They are not counted as passing.
- Targeted regression run for chat routing, model catalogue and Function
  middleware: **15/15 passed**.
- Snapshot stamping was run twice against unchanged source; both runs produced
  the same seven-character snapshot id.
- Deep audit: no blocking problems; one warning remains because
  `assets/css/mobile.css` still contains 113 legacy `!important` rules.

The full test suite should be rerun after `npm ci` completes successfully in a
normal network-enabled build environment.

## Remaining risks / follow-up items

1. `assets/css/mobile.css` still contains a high number of legacy `!important`
   overrides. They were not bulk-deleted because those overrides govern several
   older mobile breakpoints; removing them without real-device visual testing
   risks regressions. Refactor them route-by-route after visual review.
2. API in-memory rate limits are isolate-local and can reset or differ across
   Cloudflare locations. Configure WAF rate limits for production enforcement.
3. The live Cloudflare environment was not accessible from this ZIP-only audit.
   Confirm the `AI` binding and test a real chat/image request in both Preview
   and Production after upload.
4. Browser screenshot/interaction checks that depend on `jsdom`/browser tooling
   need to be rerun in an environment where `npm ci` completes.

- Test Amigo with a new setting and with an existing browser profile that had
